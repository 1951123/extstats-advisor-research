\section{Problem Formulation}

We model one captured database relation and its workload. The
\texttt{AdvisorSnapshot} is exactly $(\Sigma,S,P,W)$: portable typed schema,
fixed typed sample, population metadata, and workload. Exact or authoritative
cardinality truth is not a field of this tuple. Instead, an independently
validated \texttt{GroundTruthSet} $G$ binds to the snapshot semantic digest and
workload ID and is consumed by a replaceable \texttt{GroundTruthProvider}.
Thus the system has two inputs to utility evaluation,
\[
  \texttt{AdvisorSnapshot} + \texttt{GroundTruthSet}
  \longrightarrow \text{planner estimates} \longrightarrow \text{utility}.
\]
The fixed sample $S$ is materialized independently of $G$ and is not a source
of query truth. For a query $q$ with a truth record, write its non-negative
cardinality as $y_q$ and its planner estimate under configuration $M$ as
$\hat y_q(M)$.

The candidate universe $C$ is a frozen finite set of native statistics
designs derived from $\Sigma$ and predicate structure in $W$. Each candidate
records the relation, ordered attribute keys, supported native kind, and a
sample-built payload. A configuration $M\subseteq C$ is a set of selected
candidates subject to a candidate-row bound and search budget. The planner
evaluates $W$ under the active configuration and returns estimated
cardinalities $\hat y_i(M)$.

The v1 loss contract is \texttt{qerror-cardinality-floor-1-v1}:
\[
 Q(\hat y_q(M),y_q)=
 \max\left(
   \frac{\max(\hat y_q(M),1)}{\max(y_q,1)},
   \frac{\max(y_q,1)}{\max(\hat y_q(M),1)}
 \right).
\]
Both zero values therefore have formal semantics, including $Q(0,0)=1$.
Lower is better. Let $W^+$ be the positive-weight workload queries and
$w_q$ their workload weights. The optimization objective is the weighted
workload mean
\[
 J(M)=\frac{\sum_{q\in W^+} w_q Q(\hat y_q(M),y_q)}
              {\sum_{q\in W^+} w_q}.
\]
This weighted objective is distinct from the reporting summaries: the paper
also reports unweighted arithmetic mean, p50, p95, p99, maximum, and
improved/unchanged/worsened query counts. If a confirmatory workload has
uniform weight one, its arithmetic mean equals $J(M)$ numerically, but the
contracts remain conceptually distinct. A planner-only measurement without
$G$ is not relabeled as cardinality accuracy.

The current source supports two truth provenance kinds. In
\texttt{production-exact-execution}, safe eligible workload queries are counted
in a read-only repeatable-read source view and the artifact records the DBMS,
server version, and source-view token. In
\texttt{authoritative-external-exact}, immutable labels are imported with
authority, dataset identity, source revision, and source-artifact SHA-256; the
advisor does not pretend that it executed those labels. Both kinds use the
same utility interface after binding validation. For the current AreCEL
confirmatory protocol, the external audited observation kind is the default;
production exact execution is selected only for an independent validation or
cost measurement.

The search budget $B$ bounds the declared configuration-objective evaluations
and elapsed selection time according to the execution protocol; PostgreSQL
per-query planner calls, candidate-signal preprocessing, singleton profiling,
and independent final/full-data evaluation are recorded separately. The
search returns a \texttt{SearchResult} with selected membership $M^*$. A
separate frozen \texttt{SingletonProfile} supplies global precedence $F$, so
the deployable recommendation order is
\[
 D = F\mathbin{|}_{M^*}.
\]
The accepted greedy move order is evidence about search, not deployment order.

The distinction between membership and deployment order matters when physical
objects are interleaved with externally managed statistics. If the advisor
recommends $[A,B,C]$, a production catalog containing
$[\text{existing\_X},A,\text{existing\_Y},B,C]$ is valid as long as the
advisor-managed objects preserve $\operatorname{OID}(A)<
\operatorname{OID}(B)<\operatorname{OID}(C)$. The advisor does not require
the complete production extstats set to equal the recommendation.

The objective is consequently scoped. The optimizer evaluated $M^*$, not
necessarily $E_{\mathrm{existing}}\cup M^*$. When externally managed
statistics coexist, the SearchResult objective must not be presented as a
guaranteed objective for that combined production state. Reconciliation is a
DBA decision and is outside the advisor model.
